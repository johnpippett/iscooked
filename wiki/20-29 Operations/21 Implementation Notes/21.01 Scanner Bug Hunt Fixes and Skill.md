# 21.01 Scanner Bug Hunt Fixes and Skill
source: project_wiki
tags: [scanner, bugs, tests, skills, verification]

## Summary

On 2026-05-19, a scanner bug hunt validated three live issues with independent subagents before fixes:

- UFW `Status: inactive` was reported as active because `active` matched as a substring.
- A service bound to a concrete non-loopback address, such as `192.168.1.50:11434`, was reported as localhost-only.
- The SSL/TLS check skipped concrete non-loopback HTTP listeners and reported no non-localhost plain HTTP exposure.

## Changes

- Added bind-host helpers in `/Users/johnpippett/Coding/iscooked/site/iscooked.com`.
- Changed network exposure output to distinguish all-interface, loopback-only, and concrete non-loopback binds.
- Changed SSL/TLS probing to check concrete non-loopback bind addresses, while preserving the existing all-interface result text.
- Fixed failed curl probes so `000` plus a nonzero exit does not become a false-positive `000000` HTTP result.
- Anchored the UFW active check to exact `Status: active`.
- Updated README privacy wording to clarify local bind-address probes without implying telemetry or external calls.
- Added regression tests for Bug 10, Bug 11, and Bug 12 in `/Users/johnpippett/Coding/iscooked/tests/test_iscooked.py`.
- Added project skill `/Users/johnpippett/Coding/iscooked/skills/bug-hunt-validate-fix-review/SKILL.md`.
