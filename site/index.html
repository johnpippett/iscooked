What it examines

Seventeen places
things go wrong.

Each check reports what it saw and what it could not see. A skipped check never counts as safe.

Network & access

01.1Network exposureFind listeners on common AI and coding-agent ports.
Identifies loopback and non-loopback bindings across Ollama, LM Studio, vLLM, SGLang, LiteLLM proxy, AnythingLLM, OpenCode Server, OpenClaw Gateway, and llama.cpp RPC. A listener does not prove internet access on its own.
01.2API authenticationExamine model-list routes on identified services.
Supports Ollama, LM Studio, and vLLM on their common ports. In full scans, exposed unauthenticated endpoints correlate with Check 01 instead of double-counting the same port.
01.3Firewall statusSeparate active, inactive, and unknown states.
Reads unprivileged Linux systemd and UFW state first before falling back to privileged firewall commands, plus macOS Application Firewall and pf. A missing firewall is critical only when an AI service listens beyond localhost.
01.4Plain HTTP exposureFind exposed services that serve plain HTTP without TLS.
Probes non-loopback AI listeners for plain HTTP and falls back to HTTPS before marking a port inconclusive. Correlates score with Check 01 in full scans.

Files & secrets

02.1Model file permissionsFind model files that other users can read or change.
Examines common model directories and their permissions. Coverage depends on directory access and the model locations.
02.2Sensitive files & credential storesFind git-tracked .env files, exposed keys, and open auth stores.
Checks git-tracked .env files, world-readable .env files with API keys, and permissions on Claude Code, OpenCode, Codex, GitHub CLI, AWS, .netrc, and SSH private keys without printing secret values.
02.3History & logsFind leaked provider keys in shell history and open log dirs.
Scans Bash, Zsh, and Fish history for OpenAI, Anthropic, OpenRouter, GitHub, Hugging Face, Gemini, and AWS key patterns, plus permissions on common AI log directories.

Containers & hardware

03.1Docker configurationExamine users, privileges, sockets, and host access.
Includes host networking, daemon sockets, and host-root mounts. Metadata requests have a time limit. The scanner does not change containers.
03.2GPU exposureExamine GPU device access and management listeners.
Includes supported NVIDIA and AMD device checks. Device access alone does not establish that a system is compromised.
03.3AI processesFind known AI processes and their users.
Matches known process names and identifies processes that run as root. It does not identify every AI application.

Agents & models

04.1Ollama configurationExamine host, origin, and service settings.
Includes OLLAMA_HOST, OLLAMA_ORIGINS, and supported service-manager configuration.
04.2Browser controlFind browser debugging listeners, including custom ports.
Uses Chromium process flags, sockets, and version metadata. It does not retrieve browser tabs, cookies, or WebSocket content.
04.3MCP configurationAudit 8+ MCP clients for broad grants, plain HTTP, and unpinned npx.
Reads JSON, JSONC, and TOML configs for Claude Desktop, Claude Code, Cursor, OpenCode, Windsurf, Zed, VS Code/Copilot, Cline, Roo Code, Codex CLI, and Gemini/Antigravity. Flags broad filesystem grants, plain non-loopback http:// URLs, unpinned npx -y packages, hardcoded project secrets, and writable configs without starting servers.
04.4Coding agents & gatewaysInspect Claude Code, OpenCode, Codex, Cursor, OpenClaw, and instruction files.
Checks Claude Code bypassPermissions, wildcard Bash(*) allowlists, and project hooks; OpenCode wildcard permissions; Codex CLI approval and sandbox policy; Cursor auto-run/YOLO mode; OpenClaw JSON/JSONC gateway and exec policies; and invisible or bidi Unicode prompt-injection characters in CLAUDE.md, AGENTS.md, .cursorrules, and Copilot instruction files.
04.5Remote model codeFind remote-code flags in active vLLM, TGI, and SGLang commands.
The check examines recognized launch arguments. It does not load model code or establish the behavior of other runtimes.
04.6Telemetry settingsExamine opt-out variables and known blocked domains.
Examines supported environment variables and exact hosts-file entries. It does not analyze active telemetry traffic.
04.7Runtime versionsFlag Ollama, vLLM, and LiteLLM proxy versions with known advisories, and LiteLLM releases that shipped malware.
Reads one version route per runtime on its default port and compares it with a reviewed minimum. A current version does not rule out advisories published after the review date. It also looks in common Python environments and local Docker tags for LiteLLM 1.82.7, 1.82.8, and 1.107.0, which were published with a credential stealer, and for the files that stealer drops.

Checks can be skipped or incomplete. A low score is not a security guarantee.

curl -fsSL https://iscooked.com/iscooked.com.sha256 -o iscooked.com.sha256 &&
sha256sum -c iscooked.com.sha256 &&
less iscooked.com

2. Start it when you are ready (on macOS use shasum -a 256 -c iscooked.com.sha256).

bash iscooked.com

Before you run it.

Does it change my settings?

No. The scanner examines local settings. It does not apply fixes, start agents, or load models. You decide which settings to change.

Does anything leave my machine?

The initial command downloads the script. The scanner sends no telemetry or scan report. It probes selected local AI and browser service endpoints.

Does the report viewer upload my report?

No. Your browser reads the file. The viewer page is served with a content security policy that blocks every network request, so the page cannot send the report anywhere.

What does the score mean?

Critical findings add 10 points. Warnings add 4. Unknown, passed, and skipped results add 0, while staying visible in the counts. The maximum is 100. A low score does not establish that your system is safe.

What can it miss?

Unsupported tools, inaccessible files, missing dependencies, and configuration formats can limit coverage. A skipped check does not establish safety. Read the coverage limits ↗

Why is it called iscooked?

Because "am I cooked?" is the question you ask after you notice Ollama listening on 0.0.0.0. The scanner answers it with evidence.
