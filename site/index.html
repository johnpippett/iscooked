What it examines

Sixteen places
things go wrong.

Each check reports what it saw and what it could not see. A skipped check never counts as safe.

Network & access

01.1Network exposureFind listeners on common AI ports.
The scanner identifies loopback and non-loopback bindings. A network listener does not prove internet access or identify the application.
01.2API authenticationExamine model-list routes on identified services.
Supports Ollama, LM Studio, and vLLM on their common ports. An authentication result applies only to the route examined.
01.3Firewall statusSeparate active, inactive, and unknown states.
Examines recognized firewall backends. Missing access or an unexpected response can produce an unknown result.
01.4Plain HTTP exposureFind exposed services that use plain HTTP.
The SSL/TLS check examines common ports. It does not validate certificates or all encryption settings.

Files & secrets

02.1Model file permissionsFind model files that other users can read or change.
Examines common model directories and their permissions. Coverage depends on directory access and the model locations.
02.2Sensitive filesFind exposed environment files and ownership risks.
Uses bounded searches for key-like values in environment files. It reports findings without displaying credentials.
02.3History & logsFind possible keys in history and exposed log directories.
Examines known shell-history patterns and common AI log locations. It does not find every secret or examine every log file.

Containers & hardware

03.1Docker configurationExamine users, privileges, sockets, and host access.
Includes host networking, daemon sockets, and host-root mounts. Metadata requests have a time limit. The scanner does not change containers.
03.2GPU exposureExamine GPU device access and management listeners.
Includes supported NVIDIA and AMD device checks. Device access alone does not establish that a system is compromised.
03.3AI processesFind known AI processes and their users.
Matches known process names and identifies processes that run as root. It does not identify every AI application.

Agents & models

04.1Ollama configurationExamine host, origin, and service settings.
Includes OLLAMA_HOST, OLLAMA_ORIGINS, and supported service-manager configuration.
04.2Browser controlFind browser debugging listeners, including custom ports.
Uses Chromium process flags, sockets, and version metadata. It does not retrieve browser tabs, cookies, or WebSocket content.
04.3MCP configurationExamine filesystem grants and configuration permissions.
Model Context Protocol (MCP) checks support selected Claude Desktop, Claude Code, and Cursor JSON files. The scanner never starts an MCP server.
04.4OpenClaw gatewayExamine authentication and tool settings for selected OpenClaw CLI versions.
The check reads the OpenClaw CLI version and selected global policies in strict JSON. JSON5, includes, and unsupported overrides produce incomplete coverage.
04.5Remote model codeFind remote-code flags in active vLLM and TGI commands.
The check examines recognized launch arguments. It does not load model code or establish the behavior of other runtimes.
04.6Telemetry settingsExamine opt-out variables and known blocked domains.
Examines supported environment variables and exact hosts-file entries. It does not analyze active telemetry traffic.

Checks can be skipped or incomplete. A low score is not a security guarantee.

Before you run it.

Does it change my settings?

No. The scanner examines local settings. It does not apply fixes, start agents, or load models. You decide which settings to change.

Does anything leave my machine?

The initial command downloads the script. The scanner sends no telemetry or scan report. It probes selected local AI and browser service endpoints.

Does the report viewer upload my report?

No. Your browser reads the file. The viewer page is served with a content security policy that blocks every network request, so the page cannot send the report anywhere.

What does the score mean?

Critical findings add 10 points. Warnings and unknown findings add 4. Passed and skipped checks add none. The maximum is 100. A low score does not establish that your system is safe.

What can it miss?

Unsupported tools, inaccessible files, missing dependencies, and configuration formats can limit coverage. A skipped check does not establish safety. Read the coverage limits ↗

Why is it called iscooked?

Because "am I cooked?" is the question you ask after you notice Ollama listening on 0.0.0.0. The scanner answers it with evidence.
